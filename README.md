# Spotify Party Playlist Optimizer

Оптимизация плейлиста для вечеринки (party) по аудиохарактеристикам треков с помощью генетического алгоритма и языковой модели (LLM).

## Обзор

Репозиторий содержит два независимых метода автоматического составления плейлиста, который одновременно:
- соответствует заданному «настроению вечеринки» (целевым значениям danceability, energy, valence, tempo, acousticness, instrumentalness);
- обеспечивает плавные переходы между треками;
- сохраняет разнообразие внутри подборки;
- состоит из популярных треков;
- имеет длительность, близкую к 60 минутам.

Оба метода решают одну и ту же задачу комбинаторной оптимизации: из пула в 800 треков выбрать упорядоченный список из 20 композиций, максимизирующий единую целевую функцию `Score`.

## Датасет

Используется **Kaggle Spotify Tracks Dataset**, содержащий более 80 тыс. треков со следующими признаками (нормализованными или абсолютными):
- `danceability` (0–1)
- `energy` (0–1)
- `valence` (0–1)
- `tempo` (BPM)
- `acousticness` (0–1)
- `instrumentalness` (0–1)
- `popularity` (0–100)
- `duration_ms` (мс)

Из полного датасета для оптимизации случайным образом отбирается пул из **800 треков‑кандидатов**.

## Оптимизационная задача

**Целевой профиль вечеринки (party):**

| Признак         | Целевое значение |
|-----------------|------------------|
| danceability    | 0.82             |
| energy          | 0.78             |
| valence         | 0.72             |
| tempo           | 122 BPM          |
| acousticness    | 0.25             |
| instrumentalness| 0.08             |

**Ограничения:**
- Длина плейлиста: ровно 20 треков.
- Повторы треков запрещены.
- Итоговая длительность: ~60 минут.

**Единая целевая функция (Score):**
```
score = (0.35 × mood_fit + 0.25 × smoothness + 0.20 × diversity + 0.10 × popularity + 0.10 × duration_fit)
        × unique_ratio
        × length_penalty
```


### Компоненты Score (подробно)

1. **MoodFit** – близость среднего вектора 6 признаков (tempo нормирован в [0,1]) к целевому профилю:  
   `MoodFit = 1 – MAE(avg_features, target_features)`

2. **Smoothness** – плавность переходов между соседними треками:  
   среднее по всем парам соседних треков значение `(1 – евклидово_расстояние / √6)`.

3. **Diversity** – разнообразие набора:  
   среднее нормализованное евклидово расстояние между всеми уникальными парами треков в плейлисте (190 пар).

4. **Popularity** – средняя популярность (0–100), делённая на 100.

5. **DurationFit** – штраф за отклонение от 60 минут:  
   `max(0, 1 – |длительность_в_сек – 3600| / 1200)`.

Штрафные множители
6. **unique_ratio** = (число уникальных треков) / (размер плейлиста). Штрафует повторы треков.

7. **length_penalty** = 1 – min( |фактическая длина – целевая| / целевая, 1 ). 
   Если в плейлисте оказалось меньше или больше треков, чем playlist_size (например, после ремонта), скор умножается на этот коэффициент.

Все компоненты нормированы в диапазон [0, 1], итоговый Score также лежит в [0, 1].

## Методы оптимизации

### 1. Генетический алгоритм (`genetic_playlist_optimizer.py`)

Эволюционный подход, который итеративно улучшает популяцию плейлистов.

- **Представление особи:** упорядоченный список из 20 ID треков.
- **Начальная популяция:** случайные плейлисты.
- **Операторы:**
  - *Кроссоверинг*: обмен фрагментами плейлистов двух родителей с контролем уникальности.
  - *Мутация*: замена одного трека на другой из пула.
  - *Селекция*: турнирная или рулеточная, элитизм (сохранение лучших особей).
- **Критерий остановки:** фиксированное число поколений (100 поколений).

Параметры алгоритма (размер популяции, вероятности мутаций и кроссинговера) подобраны для достижения Score > 0.93.

### 2. LLM‑оптимизатор (`ollama_llm_optimizer.py`)

Использует локально запущенную большую языковую модель (LLM) через [Ollama](https://ollama.com/) для итеративного улучшения плейлиста.

- Стартовый плейлист генерируется случайным образом.
- На каждом шаге LLM получает текущий список треков вместе с метриками (MoodFit, Smoothness и т.д.) и предлагает замены / перестановки, которые должны увеличить общий Score.
- Модель работает как «умный мутатор»: она учитывает семантику аудиофич, а не только случайные изменения.
- Процесс продолжается до сходимости или заданного числа итераций.

Такой подход позволяет обойтись без жёстко заданных эвристик, полагаясь на способность LLM понимать закономерности в данных.

**Требование:** установленный и запущенный Ollama с моделью (рекомендуется `llama3` или `mistral`). Скрипт автоматически подключается к локальному API.

## Установка и запуск

1. Клонируйте репозиторий:
   ```
   git clone https://github.com/your-username/spotify-playlist-optimizer.git
   cd spotify-playlist-optimizer
   ```

2. Установите зависимости: 
   
   ```pip install -r requirements.txt```
   
3. Для генетического алгоритма:

```python genetic_playlist_optimizer.py```

Результат (список ID, финальный Score и метрики) выводится в консоль и сохраняется в genetic_result.json.

4. Для LLM‑оптимизатора:

4.1 Убедитесь, что Ollama запущена и модель загружена (например, ollama run llama3).

Запустите:
```python ollama_llm_optimizer.py```

Скрипт выведет промежуточные Score и итоговый плейлист.
